# ClimaGuard

Climate-driven public-health advisory dashboard.
Pipeline: 25 countries × 564 weeks of climate + disease data → feature engineering → committee-based selection → 4 models × 6 tasks → rule engine → Streamlit app.

## Structure

```
ClimaGuard/
├── data/
│   ├── raw/global_climate_health_impact_tracker_2015_2025.csv   # NOT in repo
│   └── processed/cleaned_data.csv                               # ~700 KB
├── pipeline/
│   ├── step1_clean_inspect.py
│   ├── step2_eda.py
│   ├── step3_feature_engineering.py
│   ├── step4_feature_selection.py
│   ├── step5_train_model.py
│   ├── step6_advisory.py
│   └── step7_shap.py
├── output/                # charts, advisories.csv, phase6_metrics.csv, shap_*.csv
├── models/phase6/         # best_<task>.joblib for each of 6 tasks
├── app/
│   └── advisory_app.py    # Streamlit dashboard
├── run_all.py             # orchestrator: python run_all.py [--skip-slow]
├── requirements.txt
├── Dockerfile
└── .gitignore / .dockerignore
```

## Quick start (local)

```bash
# 1. Install
python -m venv venv
.\venv\Scripts\Activate.ps1          # Windows
pip install -r requirements.txt

# 2. Run the pipeline (writes cleaned_data → features → selected → models/phase6 → output/advisories.csv)
python run_all.py                    # full pipeline
python run_all.py --skip-slow        # skip step7 SHAP
python run_all.py --from-step 4 --until-step 6

# 3. Launch the dashboard
streamlit run app/advisory_app.py    # default: http://localhost:8501
```

## What's in the repo vs regenerated on first run

The repo ships the *outputs* of every step, so the dashboard works without re-running the pipeline:

| Artefact | Size | Source |
|---|---|---|
| `data/processed/cleaned_data.csv` | ~700 KB | step1 — committed |
| `output/advisories.csv` | ~1.3 MB | step6 — committed |
| `output/phase6_metrics.csv` | ~5 KB | step5 — committed |
| `output/shap_importance_*.csv` | ~3 KB each | step7 — committed |
| `models/phase6/best_*.joblib` | ~30 MB each (RF) | step5 — committed if size allows |
| `data/raw/...csv` | large | **not** committed; place under `data/raw/` to rerun |
| `data/processed/featured_data.csv` | ~14 MB | **not** committed; regenerated by step3 |

## Deployment

### Option A — Streamlit Community Cloud (recommended, free, ~2 min)

1. Push the repo to GitHub (`.gitignore` already excludes `venv/`, `__pycache__/`, raw data, scratch files, the 204 MB legacy `models/model.pkl`).
2. Go to **share.streamlit.io** → "New app" → pick the repo, branch, and `app/advisory_app.py`.
3. The default Python version on Community Cloud is 3.13. If `requirements.txt` pins something narrower, leave it as a minimum (`>=`) and Community Cloud installs fine.
4. **Cold start**: if `models/phase6/*.joblib` are missing in the repo (excluded by size), the dashboard still runs — the headline risk class and advisory are read from `output/advisories.csv`. The "Model comparison" tab will show `NaN` latencies for missing `.joblib` files, but the metrics table itself is preserved from `output/phase6_metrics.csv`.
5. To rerun the pipeline on first deploy, add this to the Streamlit app's "Advanced settings → Secrets / Init script":

   ```bash
   python run_all.py --skip-slow
   ```

   (Takes ~3–5 min on Community Cloud's free tier; results overwrite the committed artefacts.)

### Option B — Docker (portable, runs anywhere with a Docker engine)

```bash
docker build -t climaguard .
docker run --rm -p 8501:8501 climaguard
# open http://localhost:8501
```

The image is based on `python:3.11-slim` and copies the repo minus `.venv`, `data/raw`, and intermediate 14 MB files (see `.dockerignore`).

### Option C — Render / Railway / Fly.io

Use the included `Dockerfile` — these services all auto-detect it. Streamlit listens on `:8501`; set the platform's port env var to `8501`.

## Pipeline phases

1. **Clean & inspect** — null/duplicate handling, type fixes.
2. **EDA** — histograms, country rankings, correlations.
3. **Feature engineering** — climate anomalies, interactions, lags, country-level grouping, target stratification → 163 features.
4. **Feature selection** — Pearson dedup @ |r|=0.95, then Pearson + MI + tree-importance vote (≥2/3) → top 60.
5. **Train** — chronological split (train ≤ 2022, val = 2023, test ≥ 2024). 4 candidates × 6 tasks (overall-classifier, respiratory, cardio, vector, waterborne, heat). Bit-identical via `random_state=42` and `n_jobs=1`.
6. **Advisory** — rule engine with configurable thresholds; one advisory per (country, week).
7. **SHAP** — top-feature importance per task on the test split, with beeswarm plots.

## Reproducibility

Every script pins `random_state=42`; `step5`/`step6`/`step7` call `_seed_everything()` which seeds Python, NumPy, and the relevant framework RNGs. Two back-to-back runs produce identical artefacts (verified by SHA-256 across `output/*.csv`, `output/*.json`, and `models/phase6/*.joblib`).
